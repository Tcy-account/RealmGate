# JWKS （JSON Web Key Set）

一句话：**JWKS 就是授权服务器对外公开的【公钥集合】，用来让业务服务拿到公钥，完成 JWT（JWS）验签。**
地址一般是标准路径：`https://issuer/.well-known/jwks.json`

> 
> 配套知识点：OIDC 规范里，授权服务器的元数据发现地址：`/.well-known/openid-configuration`，里面会直接给出 jwks_uri。

## 1. JWKS 的 JSON 长什么样

```
{
  "keys": [
    {
      "kty": "RSA",
      "use": "sig",
      "kid": "key-2026-01",
      "alg": "RS256",
      "n": "......",
      "e": "AQAB"
    },
    {
      "kty": "RSA",
      "use": "sig",
      "kid": "key-2026-02",
      "alg": "RS256",
      "n": "......",
      "e": "AQAB"
    }
  ]
}
```

- 外层固定字段：`keys` 数组，可以存放**多把公钥**（支持密钥轮换）
数组内单个 key 字段含义：

1. `kty`：Key Type，密钥类型。`RSA` 就是 RSA 密钥对
2. `use`：用途。`sig` = signature，**用于签名验签**（不是加密）
3. `kid`：**Key ID 密钥 ID，核心！**
4. `alg`：算法，`RS256` 代表这个密钥用于 RS256 签名
5. `n`：RSA 公钥的模数（base64url 编码）
6. `e`：RSA 公钥的指数（base64url 编码）

> 
> 注意：**这里只有公钥！没有私钥！私钥保存在授权服务器内部，绝不对外暴露**

## 2. kid 是怎么配合 JWT 工作的（重点）

JWT 的 Header 里面会带上 `kid`：

```
{
  "alg": "RS256",
  "typ": "JWT",
  "kid": "key-2026-01"
}
```

完整流程：

1. 授权服务器使用**私钥 A（kid=key-2026-01）**签名生成 JWT
2. JWT header 写入这个私钥对应的 kid
3. 业务后端拿到 JWT，先解析 header，取出 `kid`
4. 业务后端请求 jwks_uri，拿到公钥列表
5. 在 keys 数组中**找到 kid 匹配的那一条公钥**
6. 使用该公钥对 JWT 做验签

> 
> 为什么要 kid？**支持密钥轮换！**

## 3. 密钥轮换 Key Rotation（JWKS 最重要的价值）

授权服务器不能永久只用一对密钥，有安全风险，所以要定期更换密钥对：

1. 生成新密钥对：私钥 B + 公钥 B（kid=key-2026-02）
2. **不会立刻删除旧密钥**，新旧两把公钥同时放在 JWKS 里
3. 授权服务器可以逐步切换，新 JWT 用私钥 B 签名，旧 JWT 仍然能用私钥 A 签名
4. 业务后端不需要改任何配置，**自动拉取 JWKS，通过 kid 匹配公钥**
5. 等旧的 JWT 全部过期之后，授权服务器再把旧公钥从 JWKS 删掉

✅ 好处：密钥平滑切换，业务服务**不用停机、不用改配置**。

> 
> 如果没有 JWKS 和 kid：你需要把公钥硬编码写在业务代码里，一旦密钥轮换，所有业务系统必须改代码上线，非常麻烦。

## 4. 业务后端怎么使用 JWKS？

业务后端不会每次验签都请求一次 JWKS（性能差），一般做**缓存**：

1. 首次验签：拉取 JWKS，根据 kid 找到公钥，缓存公钥（比如缓存 5~15 分钟）
2. 后续验签：优先用缓存里的公钥
3. 如果验签失败，并且是 kid 找不到，就清空缓存，重新拉取 JWKS 重试（密钥已经更新了）

## 5. 常见误区

❌ JWKS 里面包含私钥

> 
> 绝对不会。JWKS 只暴露公钥。私钥留在授权服务器。

❌ JWKS 只能有一个密钥

> 
> 可以多个，密钥轮换场景就是同时存在多条公钥。

❌ 业务每次验签都要 http 请求拉取 JWKS

> 
> 不推荐，要缓存。频繁请求会增加授权服务器压力。

❌ kid 是 JWT payload 里面的字段

> 
> 错，`kid` 在 JWT 的 Header 头部，不是 payload 载荷。

## 6. 串联之前整套 OIDC 流程

1. 授权服务器生成 RSA 密钥对，公钥放到 JWKS 端点
2. 用户登录，授权服务器用私钥签名生成 id_token (JWT)，header 带上 kid
3. 业务后端拿到 id_token，解析 header 拿到 kid
4. 业务后端拉取 JWKS，匹配 kid 拿到对应的公钥
5. 使用公钥验签，确认令牌未篡改、是本授权服务器签发
6. 继续校验 exp、iss、aud、nonce 等 claims

## 一句话面试背诵

JWKS 是授权服务器对外暴露的公钥集合，通过`kid`标识每一把密钥；业务后端根据 JWT header 中的 kid，在 JWKS 找到对应公钥完成验签；核心目的是**支持密钥平滑轮换，业务端无需硬编码公钥**。
